COPY-PASTE JS (run.cjs has the full version)

  const rhino = await rhino3dm();
  const t = rhino.File3dm.fromByteArray(templateBytes);   // template-min.3dm
  const tObj = t.objects().get(0);
  const out = new rhino.File3dm();

  // once per tile
  const ef = rhino.EmbeddedFile.fromByteArray(jpgBytes);  // Uint8Array
  ef.fileName = jpgName;                                  // e.g. aerial_photo_r1c1.jpg
  out.embeddedFiles().add(ef);

  const mat = new rhino.Material();
  mat.name = 'aerial_r1c1';
  mat.setBitmapTextureFilename(jpgName);                  // must equal ef.fileName
  const matIndex = out.materials().count;
  out.materials().add(mat);

  const g = tObj.geometry().duplicate();
  const x = new rhino.Transform(1);                       // template is 100 x 100 at origin
  x.m00 = widthMetres / 100;  x.m11 = heightMetres / 100;
  x.m03 = cornerX;            x.m13 = cornerY;
  g.transform(x);

  const a = tObj.attributes();
  a.name = 'aerial r1c1';
  a.materialIndex = matIndex;
  a.materialSource = rhino.ObjectMaterialSource.MaterialFromObject;
  out.objects().add(g, a);

  // after all tiles
  const o = new rhino.File3dmWriteOptions();
  o.version = 7;
  o.saveUserData = true;
  const bytes = out.toByteArrayOptions(o);

GOTCHAS FOUND
  - setBitmapTextureFilename returns false even though it works. The filename read back
    correctly and the texture resolved, so don't treat false as failure.
  - PlaneSurface has no usable constructor and Transform.scale is uniform only. Use the
    template Brep with Transform m00/m11/m03/m13 as above. Non-uniform scale gave the
    right bbox in a 400 x 300 probe, but that probe was not written to a file or opened
    in Rhino.
  - ObjectAttributes.id is read-only. Adding the same attributes twice is safe in the
    same file: the first object kept the template's id (6DA72738-...) and the second
    was given a new id. Every export's first Picture will therefore share that id.
  - Embedded file names are stored bare, with no path. They match the texture filename.
  - TEST TRAP: if the JPGs sit anywhere Rhino searches, including a subfolder beside the
    .3dm, Rhino uses them instead of the embedded copy. My first run passed that way and
    proved nothing. Test embedding with the .3dm alone in an empty folder.

NOT TESTED
  - Running in a browser. This was Node with the same package and wasm.
  - Opening in Rhino 7. Rhino 7.4 was tried, never reached the script and was stopped

  - Real aerial sizes or many tiles. The JPGs here were 12 KB, 512 px test gradients.
  - saveUserData=false. It was set true here and the default was not checked.
